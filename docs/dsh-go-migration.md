# 迁移到 DSH Go

DSH Go 是 [ccch1mneyyy/dsh-Go](https://github.com/ccch1mneyyy/dsh-Go) 提供的第三方 Android 客户端，支持手机本机运行和远程主机。本仓库的旧 WebView 实现继续保留，后续使用上游维护的客户端。

## 采用 SSH「只连接」模式

适用于已经用 systemd 等方式管理 DSH 引擎的服务器：保留原引擎和数据，在手机中添加 SSH 主机，并选择「只连接」。DSH Go 只建立到服务器回环地址的 SSH 隧道，然后按 DSH 协议登录。

| 手机字段 | 填写内容 |
|---|---|
| 主机、SSH 端口、用户名 | 部署者自己的连接信息 |
| 登录方式 | 密码或独立手机私钥；私钥保存在仓库之外 |
| 实例管理 | 只连接 |
| 远端 DSH 端口 | 现有引擎在 `127.0.0.1` 上监听的端口 |
| DSH 登录令牌 | 该次引擎启动链接中的令牌，与旧 nginx Basic Auth 密码分开 |
| 工作目录 | 需要指定时使用服务器上的绝对路径 |

SSH 凭据负责建立隧道；DSH 令牌用于换取引擎的登录 cookie。首次连接还需要核对服务器 SSH 公钥指纹。

令牌每次进程启动都会改变；保留同一 DSH_HOME 时，已签发的 cookie 通常可以跨引擎重启继续使用。新设备或重新登录时应使用当前启动令牌。详见上游 [连接实现](https://github.com/ccch1mneyyy/dsh-Go/blob/main/packages/dsh_client/lib/src/connection.dart)。

## 已做的兼容核验

2026-11-11，对原有 DSH `0.2.0-rc.2` 进行了服务器内的基础协议检查：

- 启动令牌登录返回 303，并签发 `dsh-auth-` cookie。
- 带该 cookie 访问引擎首页返回 200。
- `/api/remote.mux` WebSocket 升级返回 101，握手校验正确。

上游客户端和其 [探测器](https://github.com/ccch1mneyyy/dsh-Go/blob/main/packages/dsh_client/bin/probe.dart) 也标注验证过 `0.2.0-rc.2`。这些检查使用服务器内的现有登录信息，历史对话和文件保持原样。

随后配置独立手机密钥，并经该密钥实际建立 SSH 隧道，再完成登录、认证首页和 WebSocket 检查。打开 `$events` 流后收到 `ready` 事件；使用同一密钥执行远程命令、向非 DSH 目标端口建立本地转发均被拒绝。密钥与连接资料仅在部署者的本机私密目录保存。

手机端登录、原生会话呈现、文件传输、后台重连和完整对话仍需单独验收，不能把协议与隧道检查写成已经完成真机测试。

## 后续验收顺序

1. 在手机安装上游 APK，添加 SSH 主机，核对公钥指纹，测试连接并保存。
2. 打开已有会话，确认内容与主机一致；新建测试会话，发送短消息。
3. 用无敏感内容的小文件检查选择、上传、实际落盘和读取。
4. 检查取消上传、重名文件、网络断开、后台切回和重新连接。
5. 若某项能力依赖新版引擎，先备份旧配置和数据，再对照上游版本说明升级，保留回退方式。
